## 2026-11-15｜课程卡片编辑与工作日首课固定色

- **现象 / 需修改项：** 详情弹窗“编辑”仅显示占位提示；编辑页不能更新原课程；课表缺少周三首课青色，要求周一至周五首课依次红、粉、青、蓝、紫，手选色优先。
- **排查与根因：** `Index.courseDetailSheet()` 的 `onEdit` 绑定占位 Toast；`AddCoursePage.save()` 固定新建课程。根目录旧 Solution 无首课规则；安卓工程 `Map/solution.md` 的“首课固定色与颜色编辑修复”明确记录 0/1/2/3/4 与手动优先。鸿蒙此前仅用课名 hash 的 `colorIndex`，未标记显式选色。
- **踩坑 / 错误记录：** 首次 ArkTS 构建因迁移异常直接 `throw error` 失败，改为抛出 `Error` 后通过。模拟器发现周次摘要初始值未随异步预填更新，改为编辑加载后显式写摘要状态，并在周次区直接绑定。保存选色后缓存的 Swiper 周页仍显示旧色，新增全表数据变化时的 `gridRevision` 重建；该重建可能加重跨 Tab 返回时的首帧跳变，另见下方方案记录。
- **改正方法：** 详情编辑入口携带原课程 ID 进入复用表单，预填姓名/教师/地点/校区/星期/节次/周次/颜色；`CourseRepository.update()` 在当前账号与课表范围内原位更新。未触碰周次时保留原离散周集合。RDB 增加 `color_override` 并对旧库事务式补列；首课固定色只应用于未明确手选色课程。八个实色选项、周/日视图及详情强调色对齐。
- **结果与验证：** 构建成功；现有 Node 用例 78 通过、1 跳过。2026-11-15 的最新 HAP 安装并启动于在线鸿蒙模拟器。实际点击周三首课→编辑，字段和青色选项预填；八色完整可见。实测选择橙色保存，重启后该课显示橙色且再进编辑选中橙色；再选青色保存恢复验收配色。最新编辑页截图显示周次 2–17 周、共 15 周。跨 Tab 返回的无跳变尚未验证，不能把本项构建成功视为该问题已解决。
- **涉及文件：** `Index.ets`、`AddCoursePage.ets`、`Course.ets`、`CourseValidation.ets`、`Db.ets`、`CourseDao.ets`、`CourseRepository.ets`、`CourseRepositoryImpl.ets`、`ShareApi.ets`、`TimetableGrid.ets`、`CourseBlock.ets`、`DayList.ets`、`CourseDetailSheet.ets`、`docs/map/` 相关地图。

## 2026-11-15｜跨 Tab 返回课表首帧跳变

- **现象 / 需修改项：** 用户截图显示从校历、成绩或我的返回课程页时，课程卡片先错位/重叠，随后恢复。
- **排查与根因：** 源码确认 `BottomTabs.navigate()` 使用 `router.replaceUrl()`，返回课程时会新建 `Index`；`Index.aboutToAppear/onPageShow` 并发启动设置、节次、课表和课程异步加载。`TimetableGrid.colW()` 在尚未测量列宽时用 `Math.max(80, ...)`，而七天模式实际列宽小于 80vp；首帧先按 80vp 计算块宽，`onAreaChange` 量到真实列宽后再收窄。`Index.gridRevision` 在课程全表变化时重建 Swiper 页，也会触发这段初始测量。用户截图与该布局路径一致；各因素贡献需录屏逐帧确认。
- **踩坑 / 错误记录：** 模拟器导航按钮自带约 250ms 滑动过渡；在过渡中截屏会看到旧页面，不能据此认定课表再次跳变。快速连续点击还可能进入其他页面，验收时需等导航过渡结束并确认目标页。
- **改正方法：** 移除 80vp 的错误下限，用页面可用宽度计算首次列宽，并在同布局下复用上次实测列宽。课程页离开时保留同进程的课程快照；新 Index 在首帧前核对账号代次、数据库账号和课表 ID，匹配才同步恢复周数、课程、节次与设置。`aboutToAppear/onPageShow` 经 `refreshPage()` 合并加载，后台核对后只在课程数据确实改变时重建 Swiper 周页；读取失败时已有快照不被清空。
- **结果与验证：** 2026-11-15 release 构建成功，现有 Node 用例 78 通过、1 跳过；最新 HAP 安装并启动于鸿蒙模拟器。实际校历→课程、成绩→课程、我的→课程往返后，课程页显示原第 11 周，卡片首行分别为红/粉/青/蓝/紫，未观察到截图中的卡片跨列重叠。冷启动与切页阶段的严格逐帧量化、五天模式和真机效果待确认。
- **涉及文件：** `BottomTabs.ets`、`Index.ets`、`TimetableGrid.ets`、`docs/map/PAGE_MAP.md`、`docs/map/STATE_MAP.md`。
- **后续待办：** 五天模式、横向翻周期间快速切 Tab、真机逐帧观感待确认。

## 2026-11-14｜课表分享菜单图标在方形格窗内偏左上

- **现象 / 需修改项：** 分享课表、导出到日程、从口令导入三行左侧的纸飞机、日历、钥匙图标没有位于浅灰色圆角方格正中心。用户截图可见图形整体偏左上。

- **结果与验证：** release 构建成功；随构建脚本执行的现有用例 59 项通过、1 项跳过。新版 HAP 已安装到在线鸿蒙模拟器并启动，转发菜单已打开供验收。截图显示图标置于格窗内；最终光学居中效果仍以用户模拟器实机观感为准。

## 2026-11-14｜登录时安全存储初始化失败

- 现象：登录导入报“安全存储暂不可用，请重试”，另有302跳转提示。
- 根因：SecretStore.createKey只判断isKeyItemExist返回false；官方HUKS文档说明密钥不存在可能以12000011拒绝Promise，原实现因此跳过生成密钥并被ensureKey转换为通用错误。日志中的12000011来自系统组件，不能直接视为本应用日志证明；应用代码缺陷与官方契约已核实。
- 修正：仅将12000011视为密钥不存在并继续generateKeyItem；其他查询异常继续失败。保持AES-GCM及原密钥别名，不删除数据，不回退明文。
- 踩坑：首次编译不允许直接throw未知类型，改为Error后编译通过。
- 结果：release构建成功，现有用例59通过、1跳过，最新HAP安装启动成功。模拟器窗口最小化且恢复失败，尚未完成真实学校登录及设备端首次密钥创建验证。
- 后续：用户重试登录，若仍失败需继续采集本应用的HUKS错误码；302需按Location和会话链路单独判断。
- 依据：https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-huks/

## 2026-11-14｜公网后台显示 Authentication required

- **现象：** 访问 http://113.45.242.182/admin 返回正文 Authentication required。
- **排查与根因：** 当前只读 GET 收到HTTP 401，响应头包含 WWW-Authenticate: Basic realm="Fuxiaowai Admin"；正文、realm与 server/server.js 的 needAuth() 完全吻合。后台 /admin 在 server.js 路由中先调用 checkAuth()，没有有效 Authorization: Basic ... 就返回401，这是管理后台预期的认证门禁，不表示管理服务崩溃，也不是福小外App口令。服务器进程启动时要求环境配置 FXW_ADMIN_USER 与 FXW_ADMIN_PASS；服务仍返回该响应说明请求到达配置了该门禁的Web链路，但不能由此确定实际配置值或浏览器是否保存过凭据。
