# 302问题修复

用户要求修复课表接口302，并以“302问题”写入Solution.md。沿API/STATE地图定位ZhengfangAuth、CasTicket、CasAuth，不使用真实学校账号/凭据自动验证。

1. 补测试：302登录跳转后仅一次换票与课表重试；200登录HTML；旧Cookie不算换票成功；成功落教务业务页；相对路径Cookie范围；外部跳转拒绝；307保留POST；取消身份阻止重试；错误响应不作为课表。
2. postTimetable保留响应信息，有限处理同教务课表目录的业务跳转；登录跳转交给fetchTimetable恢复。移除无kbList时重载首页的破坏性重试。合法JSON且kbList数组才成功。
3. CasTicket记录最后落地host/path，以状态、业务落地、非登录表单及可发送教务Cookie共同判断；CasAuth不再仅按旧JSESSIONID放行。仅输出状态与跳转类别，不输出远端正文、URL查询、Cookie或票据。
4. 通过相关回归与完整构建；核对最新产物，安装并启动模拟器，停在导入页供用户真实登录验收。学校认证端到端未测试应明确标待确认。
5. Solution.md“302问题”记录实际证据、修复、测试与模拟器结果；同步相关地图。不提交Git，不部署服务。
