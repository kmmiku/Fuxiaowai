# 兼容加固修改方案

这是实施前需求基线。当前源码、已做改造和限制见SOURCE_MAP.md，实际测试见VERIFICATION_REPORT.md；文中“待接入Android”的描述仅记录方案制定时的状态。

## 目标与技术选择

保留用户熟悉的界面、登录入口、公开方法、API及历史数据，将保护集中在存储、仓储、会话、网络与服务端边界。按用户指定的六批推进，每批可验收、可回滚。

采用现有工程内增量适配：保留Node及JSON，保留学校协议，客户端在公开Store/Repository背后增加内部实现。整体重写客户端、立刻替换RawHttp、切换服务端数据库会扩大兼容面，不纳入本轮。整表同步仍为覆盖，手动修改冲突合并另立需求。

Android待接入源码后沿用其既有架构；HUKS不能直接用于Android。Android使用Android Keystore管理不可导出的密钥，内部AES-GCM封装必须按实际minSdk和设备能力验证，不静默降级明文。鸿蒙沿用HUKS。两个平台保留各自现有对外签名，示例ArkTS接口不能凭空变成Android公共API。

## 兼容合同

| 范围 | 冻结内容 | 证据 |
|---|---|---|
| UI | 结构、尺寸、颜色、动画、按钮位置、导航 | 固定设备/系统/字体/主题/数据截图及操作录像 |
| 登录 | 教务直登、CAS、验证码、企业微信扫码 | 三条认证链及验证码分支脱敏回放与设备验证 |
| 本地接口 | 现有公开方法名、参数、返回类型 | 源码签名清单、调用点与编译 |
| 服务端 | 全部现有路径、方法、成功响应字段与旧可选字段行为 | 以实际生产匹配源码和旧客户端样本冻结；不拿工作区设计替代生产 |
| 数据 | 课表、成绩、账号、设置、原有分享口令 | 升级前后数量、归属、字段和值的私有校验 |
| 发布身份 | 鸿蒙bundleName及合法签名链；Android applicationId及签名证书更新链 | 原发布包验证结果，仅存证书指纹等非秘密信息 |
| 旧客户端 | 后端升级后继续正常分享、读取、反馈 | 最低仍支持版本及当前发布版本安装包回归 |

允许据实修正隐私文字、错误提示、错误结果；逐项记录必要差异，不能以安全改造为由重做UI。成功响应中的时间、随机ID等按字段规则比较，稳定字段逐一比较。

## 参考实现与具体任务

下表路径均相对参考鸿蒙根目录；Android目标文件需批次1盘点后填写，不预造类名。任务1—15对应用户原需求。

|任务|参考落点/现状|实施要求与完成证据|
|---|---|---|
|1 异常与校验|`server/server.js`，文档已有readBody/validShare/入口捕获|核对线上差异后补边界；拒绝null、数组冒充对象、类型错误、越界星期/节次/周次、超长字符串/图片；旧可选字段补默认。按既有错误风格返回，不能泄漏堆栈；请求级异常关闭本次响应，不用全局uncaughtException吞错继续运行。异常序列后正常请求成功|
|2 文本渲染|`server/admin.js`已有textContent；后台v2已独立上线|盘点全部动态DOM插入，普通值用textContent；图片只允许受控后台图片路由、白名单文件名，同源也禁止任意路径。按真实脚本/样式/图片需求制定CSP，先报告再收紧，不用unsafe-inline一概放开。XSS样本和全部后台操作回归|
|3 加密与日志|`data/local/SecretStore.ets`、CredentialStore/SessionStore、`common/util/PrivateLog.ets`|保留load/save调用；读旧明文→加密副本持久化→读回解密比对→切版本→删除明文。各步骤故障均可重试，不先删旧值。覆盖密码、Cookie、票据、扫码凭证、口令及URL查询/异常日志；Android使用Keystore适配|
|4 秘密分离|`server/fxw.env.example`、构建和签名脚本|文档、样本不含真实秘密；生产凭据运行时注入，缺配置拒启；签名材料在工程外显式传入。已暴露凭据列入独立轮换记录；删除文档不等于历史秘密失效，不擅自换发布密钥|
|5 事务与恢复|`data/local/Db.ets`、`dao/CourseDao.ets`、`data/repository/CourseRepositoryImpl.ets`参考已有事务/SerialQueue|全部校验在删前，队列内事务删+插；删除课表/多写修改同样事务化；查直接DAO写是否绕队列，禁止嵌套队列死锁。中途失败/杀进程后只能得到完整旧表或新表|
|6 主键迁移|参考当前course.id仍是TEXT主键，DAO编码账号/表/原ID|不能把编码方案误写成已实现复合约束。先验证编码可逆及旧ID映射；若建新内部主键，新表唯一键至少含account_id、table_id、course_id，保留对外Course.id原值。旧courseId方法以当前账号/表或唯一映射定位；多候选返回明确错误，禁止跨表全删。备份后事务迁移，核对数量/归属/冲突再切版本|
|7 会话协调|`app/di/ServiceLocator.ets`、AccountScope/SchoolTraffic、GradeSync|统一捕获accountId+sessionRevision，任务合并键包括账号与代次；每次持久化和UI发布检查。补ProfileStore保存、反馈回调、首页异常分支、扫码取消/验证码失败恢复；失效同时尽力取消传输。A→B/A→退出竞态不写回A|
|8 清理收口|`Locator.clearPersonalData`参考已有，但清全部账号且权限失败会中断|内部按入口定义清课表/退出/撤回范围，公开入口保持；首先失效任务，逐项清凭据/缓存/账号数据/头像/反馈/分享/WebView/提醒/日历/卡片。每项记非秘密结果，失败继续其他清理并可重试；清缓存不得误删待发图片。云端删除另行实现和确认，退出不宣称已删云端|
|9 学期元数据|`TimetableStateStore.ets`、TermCalendar、SchoolCalendar|参考已有按账号/表学年、学期、首周周一、总周数；补来源与同步时间、统一首页/分享/提醒/日历/卡片读取；旧数据仅使用已核验配置初始化，记录配置版本/出处，不按月份猜。课程与元数据非同库时需持久提交日志防半提交|
|10 完整成绩|`data/remote/GradeSync.ets`、GradeCacheStore、GradeAdapter|参考已有分页和全成功才保存，但学期范围仍有入学年推断边界。核对学校实际学期集合、分页总量及上限命中错误；内部逐学期状态，失败保留旧缓存；本轮保留整批完整后发布，失败不更新时间，网络错不写空结果。缓存可读和会话有效分开|
|11 覆盖快照|SyncTimetable、CourseRepositoryImpl、ShareApi|维持整表覆盖；覆盖前保存最近成功版本（课程+学期+节次+账号/表）并校验。事务提交前失败保留旧表；跨库文件失败以提交日志恢复，不能把备份失败伪装覆盖成功。不引入自动合并|
|12 反馈队列|FeedbackStore/FeedbackDelivery/ShareApi、`server/server.js`|参考已有429延迟、稳定ID、压图和成功清图；补网络切换/重启的去重。当前IP+requestId会因IP变化重复，需兼容旧请求的可选幂等键策略、内容指纹冲突检查与有效期，保留JSON兼容；无header旧客户端继续可用。按JSON UTF-8实际字节检查，不能只算图片二进制；同意图重试不生成新ID。满队列拒绝新入队并明确提示，不丢待发项|
|13 系统集成|CalendarExport、TimetableStateStore、WidgetRefresh/EntryFormAbility|按设备能力排提醒，移除固定3条但遵循系统配额；记录每个自有提醒/事件ID、业务key与写入状态。写成功后记录失败的窗口需要对账，重试不能盲目再建。跨账号/表更新只处理本应用登记对象；卡片冷启动与首页同源|
|14 网络加固|`network/http/RawHttp.ets`、HttpClient/CookieJar、认证模块|参考已有8MiB限制、chunked/gzip/deflate，仍逐项验证截断、解压炸弹、超时释放、相对重定向、取消、域/端口/协议白名单、Cookie过期/host-only/path/secure。跨域跳转不泄漏认证头。保留get/postForm签名；不直接替换传输层，不转发学校凭据到自建服务|
|15 后端运维|server.js、nginx.conf.example、fxw-share.service、OPERATIONS.md|参考已有异步/原子写/缓存/容量；补并发配额强一致或保守预留，原子rename不等于断电持久化，按需要fsync文件/目录。JSON+图片以暂存/提交及孤图回收协调。指定代理且由nginx覆盖头；校园出口共享IP限流结合全局容量、请求节奏与业务标识，不凭可伪造header绕限制。告警覆盖磁盘、写错、事件循环、失败率、备份恢复|

学校HTTP链路仍是已知限制。本轮没有核验官方HTTPS入口；后续通过学校官方资料/管理员核实并实测，再决定接入，不能直接把URL改成https或宣称全程安全。

## 六批门禁与依赖

|批次|交付范围|通过后才能进入下一批|回滚点|
|---|---|---|---|
|1|源码定位、版本/包/接口/UI基线、数据及签名恢复流程|相同源码可构建，原发布包身份可核验，备份在隔离环境可恢复|源码提交+构建配置+私有数据备份清单|
|2|任务1、2、4及3中的日志清理|旧正常样本兼容、恶意数据文本显示、连续错误不影响服务、后台v2不退化|服务源码/资源及匹配环境配置版本|
|3|任务3、5、6、7、8、11|明文迁移/主键迁移失败不丢数据，事务和账号竞态通过，快照可恢复|迁移前数据库/偏好/文件一致备份+旧安装包|
|4|任务9、10、12、13|学期同源、成绩完整、反馈可重试、系统写入幂等、权限失败可恢复|本地数据与系统对象登记备份；共享服务独立回滚|
|5|任务14、15及反馈后端去重部署|全部登录/学校请求同一回归集通过；配额/重启/磁盘/代理测试通过|服务及数据、代理配置、客户端构建|
|6|全套UI、升级、旧客户端、签名安装及恢复演练|证据齐全且无未解释差异；所有承诺标记有验证依据|正式产物哈希+源码提交+匹配备份|

每批先写失败用例，确认能复现，再实现最小改动并跑回归；保存证据后独立提交。批次不是单一大提交；客户端和共享服务分别记录提交/部署/回滚。后台v2交付日志称旧口令未改，不能据此假定其余后端加固已上线，也不得重复执行日志中清空旧反馈的部署动作。
