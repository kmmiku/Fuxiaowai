# 执行手册

本文件保留实施前步骤。当前已接入源码并完成本地改造，执行结果见VERIFICATION_REPORT.md；日常启动使用根AGENTS.md和tools/Start-Android.ps1。后续正式发布仍须执行本文件的备份、验收与恢复门禁。

## 1. 接入正确源码

在PowerShell确认位置及状态：

```powershell
Set-Location -LiteralPath '<本目录：仓库内 android/>'
git status --short
git remote -v
Get-ChildItem -Force
```

当前没有提交。将真实Android源码放入此目录，或在单独目录检出正确远端，再迁入本Map；不要运行git clean/reset覆盖已有文件。若实际要维护鸿蒙，则进入仓库内 `harmonyos/`，先读该目录 AGENTS.md 及 git 状态，保留其已有未提交改动。

接入后检查：

```powershell
rg --files -g AGENTS.md -g '*gradle*' -g 'AndroidManifest.xml' -g 'gradlew*' -g 'package.json' -g 'server.js' -g '*test*' -g '*Store*' -g '*Repository*'
```

补一份Map/SOURCE_MAP.md，列出启动入口、页面、登录三链、课程仓储/迁移、账号会话、成绩、反馈、提醒/日历/卡片、网络与后端的真实文件及函数，记录读取的源码提交。Gradle/JDK/SDK版本取工程配置，不预设最新版本，不借本轮做依赖升级。

## 2. 建立可还原基线

- 确认哪些改动属于既有工作；只选择已审阅且无秘密的文件加入版本控制，不用git add .。
- 在有首个基线提交后创建 `codex/compat-hardening` 分支，记录基线提交SHA。空仓库现在不能打有效版本标签。
- 在工程外受限目录保存数据库、Preferences、课程/成绩/图片、配置版本及清单；先暂停写入/后台任务，或使用平台支持的一致备份。SHA256清单也按私有数据保存；秘密和私钥不入Git。
- 在隔离设备/服务副本恢复，核对账号/课表/课程数、归属、学期、成绩与分享口令可读性。迁移前备份不能只复制正在写入的数据库主文件；考虑WAL和相关文件。
- 基线请求需覆盖成功、失败、验证码、过期、无数据和旧可选字段。脱敏保持结构/类型/长度关系/跨请求关联，重新生成假图片，清理URL查询、header、HTML隐藏票据、二维码和截图中的个人信息；不可回放真实票据。
- UI固定设备型号、OS、分辨率、缩放/字体、主题、时区、语言、课表数据及动画取帧规则；登录流程录制基线。禁止把未采集的截图标成一致。

## 3. 每批执行循环

1. 读取CHANGE_PLAN对应任务，核实当前保护，记录“已有且通过/已有待修/缺失”。
2. 先在隔离数据中添加能暴露问题的测试，运行并保存失败原因。
3. 在原公开接口背后实现；每次只完成一个可独立验证的任务，避免UI改版和无关重构。
4. 跑本任务、受影响接口、上一批必要回归；设备权限、学校协议和跨进程卡片另做真实验证。
5. 更新ACCEPTANCE条目：提交SHA、命令、退出码、证据位置、未覆盖边界；审查差异中是否出现秘密。
6. 明确选择文件提交并建立批次回滚标签；不把本地测试通过写成生产已发布。

Android测试/构建命令在接入后依据Gradle模块和任务确定；目前没有gradlew，不能声称 `assembleDebug`、`test` 或签名任务可运行。

鸿蒙参考工程已有下列验证入口，仅在该目录且检查脚本后执行：

```powershell
node --test tests/storage.test.cjs tests/credentials.test.cjs tests/account.test.cjs
node --test tests/grade-sync.cjs tests/grade-cache-atomic.cjs tests/feedback-delivery.cjs
node --test tests/server-http.cjs tests/admin-console.cjs
node --test tests/network-raw.cjs tests/network-compression.cjs tests/network-cookie.cjs tests/network-client.cjs
```

这些是参考已有命令，测试依赖本机SDK/替身或临时环境，本轮未运行。后台浏览器测试还需外部playwright-core配置 `FXW_QA_PLAYWRIGHT`；不能据测试文件存在判定通过。构建、打包和验包入口见参考 `docs/map/BUILD_MAP.md`，运行前检查其签名输入和副作用。

## 4. 服务端独立发布

- 使用生产匹配源码副本比较工作区差异，保留已上线后台v2。冻结路由矩阵，脱敏旧JSON做fixture，先在临时FXW_ROOT和非生产端口运行。
- 不在命令行或日志打印真实环境变量。测试缺少后台配置必须拒启，测试环境注入假账号密码；生产凭据从既有受限环境文件/秘密系统注入。
- 先备份源码/资源、受限配置与数据，验证健康、认证、分享读写、反馈及旧口令哈希；压测只在隔离副本进行。
- 发布前给出具体文件差异、测试结果、配置变更与恢复包。执行生产发布须属于用户明确授权范围，本次“给出方案”不包含生产部署。
- 不重跑参考 `tools/deploy-admin-console.py`：日志说明含清空反馈的真实动作。不要用整个工作区server.js直接覆盖线上。
- 发布后核验healthz、认证边界、旧口令未被重写、旧客户端流程、磁盘/写错/事件循环/失败率；保留无敏感内容的部署记录。

## 5. 回滚顺序

无数据结构变更：停止相关写入，恢复对应源码/配置/静态资源，启动后做健康、认证和旧客户端回归。后台UI回滚不覆盖tickets。

有数据迁移：先停止新写入和旧后台任务，保全故障现场；恢复旧程序与同一回滚点的数据库、偏好、文件、账号选择及学期配置，再启动验证。不得只回退程序。Keystore/HUKS密钥有设备绑定约束，文件备份不等于密钥可跨设备恢复，迁移演练应在匹配身份的同设备副本/受支持环境进行，不能把解不开的密文当恢复成功。

系统日历/提醒是外部副作用，按登记ID和业务key对账补偿；回滚数据库不能撤销已创建事件。云端发布后产生的新反馈/口令须单独保全并对账，禁止为程序回滚整目录覆盖掉新数据。记录维护窗口内可能丢失的变更，不能承诺未验证的零损失恢复。

## 可以直接下达的执行指令

源码接入后，按以下顺序逐批发起即可：

> 按Map执行批次1：定位真实源码，补SOURCE_MAP，采集脱敏接口和固定UI基线，在隔离环境验证备份恢复；只报告有证据的结果，不部署、不改签名。

> 按Map执行批次2：先核对现有加固，补XSS、输入校验、请求级异常和敏感日志；保持公开接口及后台v2；完成回归并列出差异。

后续分别执行批次3、4、5、6；每次带上上一批验收记录。任一批未过门禁，先解决失败，不跨批扩大范围。
